# Maqtomate Customer Website Blueprint

**Status:** Implementation blueprint for a public, worldwide SaaS marketing surface. This document avoids unverified customer metrics, fictional reviews, and claims for features not yet live.

## 1. Positioning

> **Maqtomate is the managed WhatsApp AI Employee for businesses that need every customer message answered, qualified, escalated, and reported without running a Meta developer setup themselves.**

The public website should sell an operational outcome rather than a chatbot builder. Maqtomate is positioned for founder-led and service businesses that need a managed, official WhatsApp Cloud API deployment with tenant-isolated operations, not an unofficial QR-session automation tool.

## 2. Audience and conversion model

| Audience | Core pain | Page promise | Primary CTA |
|---|---|---|---|
| Sales-led service business | Enquiries arrive after hours and follow-up slips | Qualify intent and hand serious enquiries to the right person | See the AI Employee workflow |
| Appointment-driven business | Staff repeat the same questions and chase bookings | Answer, collect context, and prepare a clean handoff | Build my WhatsApp workflow |
| E-commerce team | Product and order questions fragment across chat | Ground replies in business information and escalate exceptions | Explore commerce automation |
| Agency / operator | Client WhatsApp systems are hard to operate safely | Give each business an isolated operating workspace | Talk to an automation specialist |

Initial conversion remains assisted and payment-gated. The site must not promise immediate public self-service activation until the approved Meta Embedded Signup flow is implemented and verified.

## 4. Homepage module order

1. **Outcome hero.** Explain the AI Employee outcome, official Meta-only operation, and dual CTA.
2. **Product operating loop.** Visualize the exact `Customer message → AI understands → lead context → human escalation → report` path.
3. **Capability proof.** Text response, voice-note transcription, lead qualification, handoff, reporting. Each module must distinguish live capability from planned capability.
4. **Use-case selector.** Real estate, clinics, salons, education, ecommerce, professional services.
5. **Managed connection.** Explain that Maqtomate manages official onboarding; customers do not receive developer-dashboard tasks or credentials requests.
6. **Trust boundary.** Official Meta API only, server-side encrypted tenant secrets, isolated workspaces, owner-approved activation.
7. **Launch path.** Discover → configure → supervised test → activate.
8. **FAQ.** Address number ownership, personal WhatsApp protection, data handling, human handoff, and activation prerequisites.
9. **Final CTA.** Request an AI Employee workflow assessment.

## 5. Design system

The public surface should retain the command-system dark navy and restrained signal-mint language of the Owner Console while shifting from operations UI into buyer clarity. Use a deep ink background, bright but accessible mint for real system states and CTA emphasis, off-white type, copper/amber only for gated or pending status, and a precise grid with product diagrams rather than stock illustrations. Avoid generic chatbot gradients, copied device screenshots, or fake customer-logo walls.

## 6. Compliance boundaries

- Use only official Meta WhatsApp Cloud API positioning.
- Do not claim calling, call recording, permanent customer activation, embedded signup, CRM sync, Google Sheets/Excel sync, or self-serve configuration as live until individually verified.
- Never show a customer credential, secret, token, webhook URL, private phone number, or owner recipient on a public page.
- The owner’s personal WhatsApp is never a customer-facing sender, never an onboarding option, and never a public contact number.
- No invented customer reviews, testimonials, ratings, logos, results, traffic, or uptime metrics.
